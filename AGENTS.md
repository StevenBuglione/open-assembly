# Project contract

Read docs/plan.md and docs/adr/0001-project-scope.md before work. The user
approved project setup followed by GPT-6.1 subagents at xhigh reasoning.
The coordinating agent performs setup, supervision, review, and integration.
Implementation belongs to the delegated agents.

The user authorized continuous implementation through the roadmap, starting
with Phase 1 on top of the accepted Phase 0 foundation. Use each phase's exit
gate to measure completion and continue authorized work at the checkpoints.
Never label libc complete or a function verified merely because a scaffold
or test fixture exists.

# Non-negotiable rules

1. Shipped runtime, libraries, extensions, and applications are hand-authored
   NASM for x86-64 Linux System V, static non-PIE, baseline SSE2. C is allowed
   only under tests/ and generated uncommitted build/include/c/ headers.
   Python and shell are permitted for development tools. No compiler output
   or third-party implementation is committed as assembly.
2. Each public function requires a TOML specification and generated assembly
   comment header. Specifications contain no hand-written status.
3. Tests name their independent oracle. The test-author session reads specs
   and shared contracts, never the implementation being tested.
4. tests/oracle/ and tests/external/ are protected, append-only paths.
   Never delete or weaken existing assertions. Protected changes require
   owner review. Initial fixture creation is authorized by this setup task.
5. New function tests must fail against an automatically generated stub.
6. Record provenance per function. Allowed algorithm sources are original
   work, musl, fdlibm, Ryu, CORE-MATH, and ARM optimized-routines, subject to
   their actual per-file licenses. No glibc or GPL/LGPL source translation.
   glibc may be executed as an oracle.
7. Only src/x86_64-linux/internal/ may issue syscalls. Runtime and public
   functions call the private boundary. errno is TLS from the first runtime.
8. After three failed function gates, record docs/blocked/<name>.md and stop
   that function. Harness integration failures are tracked separately.
9. Run a full regression for changes to internal/ code and shared assembly
   macros. The owner authorized implementation and review fixes in support of
   the roadmap. Keep changes to established internal ABI contracts explicit
   and subject to owner review in the corresponding PR.
10. No fabricated coverage, mutation scores, or pass evidence. Unsupported
    checks must fail closed or be explicitly reported as pending. Evidence
    is generated by executing checks and includes source/tool identity.
11. Preserve callee-saved registers, stack alignment, DF, MXCSR control bits,
    and x87 control state. Extend narrow arguments before use. Every assembly
    file needs a non-executable .note.GNU-stack section. Fail closed on
    control flow or instructions the static checker cannot analyze.
12. Work only in assigned paths, coordinate shared interfaces, and do not
    commit, push, or alter another agent's files without coordination.

# Validation

Use the pinned toolchain with tools/container COMMAND once available, or
`nix shell nixpkgs#devenv --command devenv shell -- COMMAND` during setup.
Phase 0 must include a positive control as well as rejection of approximately
30 independent seeded bugs and a semantically wrong strlen. Rejections must
be attributable to the expected defect, never merely absent headers or a
crashed tool. Test objects use -ffreestanding -fno-builtin and symbol checks.

The overall roadmap and future gates live in docs/plan.md. Pending future
capabilities must be listed honestly in the milestone report.
